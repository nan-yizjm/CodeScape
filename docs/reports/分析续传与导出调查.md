# 分析续传与 SVG 下载调查

日期：2026-10-23。关联 [Issue #6](https://github.com/nan-yizjm/CodeScape/issues/6)。

## 调查结论

“解析”包含本地静态索引、模型分批分析和发布前校验。当前可确认有续传缺陷，以及模型返回结果反复触发契约校验的记录；不能据此给出所有项目的失败率，或把模型服务错误归因于静态解析器。

- 本机已有的 20 条结构校验反馈中，11 条涉及重复或越界的讲解实体，5 条涉及函数归属，3 条涉及补读范围，1 条为空架构。这是修复尝试的反馈条数，不是 20 个失败任务，也不是新增模型评测。
- 输出截断后动态拆批，只完成部分子批时，旧逻辑可能丢失可复用进度；同一函数跨多个片段、纯文本和配置文件还可能因成员集合相同而误判整批完成。
- 下载目录的 16 份 SVG 均为 2026-10-11 大图验收产生的“人工图”。与[当时的验收记录](p0/开发与验收记录.md)一致。生产代码仅在点击“导出 SVG”后下载，没有分析完成后自动下载的路径。连续手动点击仍会产生独立下载，不据此伪称发现自动导出缺陷。

## 修复

1. 每个新完成批次由应用记录真实文件行范围，以独立检查点封装写入文件；父进程、AI 工作进程、落盘和恢复均传递范围。该信息不进入模型输出 schema 或公开架构 API。
2. 恢复同时验证范围边界、实体和模块路径一致性、源码依据及完整行覆盖，按已保存的切点恢复部分批次。完整的新范围记录优先于残留旧片段；未覆盖的行和配置文件继续处理。
3. 旧检查点缺少范围时，不再仅凭多个结果的函数并集推定源码已读完。可拆分单元保留旧记录并重新处理，不能把无法证明的完成度当作完成。这可能使旧任务重新分析相应内容，但不会静默漏读。
4. 检查点封装格式或范围损坏时明确暂停，保留原文件，不静默清空后重新发送。
5. 对重复、越界讲解给出具体去重和本批范围说明；补读反馈明确 200 行、20,000 字符及累计 80,000 字符限制。不放宽引用验证、不增加重试上限、不回显任意模型错误内容。

## 验证边界

使用应用自有人工源码和固定模型响应，覆盖首子批中断、长函数重叠片段、无函数源码、配置文件、连续前缀、范围间隙、旧格式多次拆分、无效范围、实际工作进程 IPC 和落盘恢复。目标仓库的代码没有运行；本轮没有真实模型请求或新增模型费用。

- 后端全量 540 项通过（本轮新增 43 项），前端既有 53 项通过。
- TypeScript 检查、生产构建、Ruff 与 `git diff --check` 通过。
- 独立复核补查旧格式跨多次拆分的尾段漏读问题，修复后复核通过。
- 仍有既有 Starlette TestClient 弃用提示及源码阅读器构建分块大于 500kB 的提示。

服务限流、断网、上游模型错误以及有限修复仍不合格时，任务依旧可能暂停。全局职责整理与概览的独立阶段检查点未在本轮增加；这些是后续优化空间，不以放宽源码证据校验换取表面成功。

本轮交付源码修复，不重制既有安装包或修改历史版本标签。
