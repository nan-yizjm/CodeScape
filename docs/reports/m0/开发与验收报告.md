# M0 首轮开发与验收报告

日期：2026-10-09

版本：v0.1.0 开发预览

结论：**首个可运行原型已完成本轮检查；M0 总体验证和 P0 最终验收尚未完成。**

## 本轮实现

React + React Flow + ELK Web Worker 提供项目学习库、模块下钻、内部函数图和单侧详情面板。函数源码来自只读快照，显示全文与行范围高亮。同向调用合并为一条边，证据逐条保留；自递归单独呈现；跨模块调用只作存在性标记。SVG 导出包括当前层级全部节点，不依赖当前视口。

FastAPI 提供本地接口，SQLite WAL 保存项目、学习状态和探索层级/视口。学习状态使用修订号，两个并发写入只允许一个成功。原型数据表使用 `prototype_` 前缀，后续正式数据模型按开发设计迁移。

Python 使用 AST 与保守绑定；TypeScript 使用 Compiler API；C/C++ 使用 Tree-sitter 与 libclang。匿名、嵌套、推导式和构造/析构中的调用保留真实作用域。函数别名、参数回调、已识别虚分派、歧义实现不作为确认直接调用。

DeepSeek 是主要接收端，模型为 `deepseek-flash`。提供兼容 Chat Completions 设置、无源码连接测试、明确的源码发送授权、有限重试、JSON 契约与实体归属校验。密钥已保存在仓库外的 Windows DPAPI 加密文件，设置接口不返回密钥。切换接收端后必须重新授权；运行任务时禁止切换设置。

## 浏览器实际验证

使用 playwright 技能，在 1440 × 960 浏览器中检查以下流程：

1. 打开项目库，进入样例模块图，显示 3 个模块、2 条模块协作边。
2. 进入分析引擎，显示 4 个内部函数与 4 条聚合边，包含自递归与跨模块存在性提示。
3. 打开函数详情并修改学习状态；刷新页面后，学习进度与探索层级保留。
4. 打开 `walk_syntax` 全文源码，定位第 20–28 行，查看只读高亮。
5. 点击 `parse_source → walk_syntax` 连线，显示第 15、16 行两条独立证据。
6. 下载当前层级 SVG。
7. 打开 AI 设置，显示 DeepSeek 地址、指定模型和空的密码输入；不显示已保存密钥。
8. 通过界面导入本地三个样例文件，静态索引就绪，识别 8 个函数和 9 处调用；未授权时不产生语义架构。

首次真实导入暴露 Windows 子进程中文 JSON 编码不一致。已统一工作进程输入输出 UTF-8，补充包含中文函数的回归测试，重新导入成功。初轮控制台未见错误；设置页出现一条密码输入框未放入 form 的浏览器提示，无密钥内容。

截图位于本地 `output/playwright/`，不提交浏览器会话、启动凭证或跟踪文件。原始被分析样例未执行，快照测试同时核对了原始字节保持不变。

## 用户操作式验收

1. 按根目录 README 准备依赖并执行 `Start-CodeScape.ps1`。
2. 打开“源码学习样例”，确认“模块人工预置 · 调用静态提取”标识。
3. 进入“分析引擎”；点击信息按钮打开函数详情，点击函数打开源码，两种操作相互独立。
4. 查看两次调用对应的证据行，修改一个函数为“学习中”或“已掌握”，重新打开项目检查状态。
5. 点击“导出 SVG”，确认导出的节点数量与当前层级一致。
6. 导入自己的本地源码目录，检查排除项和解析诊断。需要真实 AI 分析时，由用户在界面确认当前接收端与源码范围。

- M0 尚缺代表性固定仓库的精确 manifest、人工关系基线、完整语言支持矩阵、受控补读验证、大图/双向关系/SVG 独立查看器检查。当前不能宣称 M0 总体验收通过。
- M1/M2：Git 导入、范围匹配器的完整 `**` 语义、多阶段受控补读、函数讲解、完整任务队列、检查点、模型上下文探测和用量账本。
- M3：C/C++ 编译数据库、可信系统声明、模板实例/特化、运算符、宏条件配置；Python 动态名称改写；TypeScript 动态分派与完整诊断；跨语言双侧证据。当前 C/C++ 无法验证的 include 会降级整批语义解析，不能当作完整支持。
- M4：不可变分析发布版本、跨版本学习迁移、模块学习状态、隐藏作用域到模块关系的可靠投影、同级模块展开、完整面板历史恢复、取消/删除、性能与异常恢复。

原型暂只支持不带 BOM 的 UTF-8。源码读取校验快照哈希与版本；带 BOM 文件明确列入排除项，避免字节偏移假定位。AI 上下文会自动按文件和行范围拆分为受控批次，无法放入单个批次时仍会明确报错，不会默默截断源码。分析中断后不自动恢复付费请求。

下一步优先补齐 M0 剩余的真实仓库和边界证据验证，再进入全量流水线实现。此报告记录实现事实，不替代完整 [测试计划](../../CodeScape_Test_Plan.md)。

## 超大项目分批分析

针对 AIHOT 等源码范围较大的项目，AI 分析已从单批保护提示升级为受控分批流程：服务先按文件估算上下文，必要时按行范围切分；每批独立请求并校验函数归属、源码路径和模块证据，全部批次完成后合并模块与概览。分析进度会持久化为“已完成/总批次”，页面实时显示当前批次；失败或中断会保留暂停原因，并提供“重新开始分批分析”入口。

固定响应测试覆盖两批上下文的规划、逐批进度、用量合并和最终实体归属校验。本轮未对 AIHOT 或其他用户源码发起真实 AI 请求；真实上传仍需在项目页面明确授权。
