## 本轮实现

React + React Flow + ELK Web Worker 提供项目学习库、模块下钻、内部函数图和单侧详情面板。函数源码来自只读快照，显示全文与行范围高亮。同向调用合并为一条边，证据逐条保留；自递归单独呈现；跨模块调用只作存在性标记。SVG 导出包括当前层级全部节点，不依赖当前视口。

FastAPI 提供本地接口，SQLite WAL 保存项目、学习状态和探索层级/视口。学习状态使用修订号，两个并发写入只允许一个成功。原型数据表使用 `prototype_` 前缀，后续正式数据模型按开发设计迁移。

Python 使用 AST 与保守绑定；TypeScript 使用 Compiler API；C/C++ 使用 Tree-sitter 与 libclang。匿名、嵌套、推导式和构造/析构中的调用保留真实作用域。函数别名、参数回调、已识别虚分派、歧义实现不作为确认直接调用。

DeepSeek 是主要接收端，模型为 `deepseek-flash`。提供兼容 Chat Completions 设置、无源码连接测试、明确的源码发送授权、有限重试、JSON 契约与实体归属校验。密钥已保存在仓库外的 Windows DPAPI 加密文件，设置接口不返回密钥。切换接收端后必须重新授权；运行任务时禁止切换设置。

## 用户操作式验收

1. 按根目录 README 准备依赖并执行 `Start-CodeScape.ps1`。
2. 打开“源码学习样例”，确认“模块人工预置 · 调用静态提取”标识。
3. 进入“分析引擎”；点击信息按钮打开函数详情，点击函数打开源码，两种操作相互独立。
4. 查看两次调用对应的证据行，修改一个函数为“学习中”或“已掌握”，重新打开项目检查状态。
5. 点击“导出 SVG”，确认导出的节点数量与当前层级一致。
6. 导入自己的本地源码目录，检查排除项和解析诊断。需要真实 AI 分析时，由用户在界面确认当前接收端与源码范围。

## AIHOT 高层抽象视图

AIHOT 的 378 个根逻辑模块直接平铺会造成依赖线和节点堆叠。前端现在在架构全景中按稳定源码路径生成抽象代码域：默认只显示 5 个高层节点，展开“核心包”后显示后端核心、契约定义等子域，再展开后端核心显示内容发布、信源采集、事件归并等下一层；继续点击才进入真实逻辑模块和函数证据。抽象层只做展示聚合，不修改 AI 结果、学习状态或原始源码归属。

AIHOT 实际浏览器验收确认：全景视图为 5 节点、5 条域级依赖（域内 confirmed 调用以自环提示）；应用服务层归并为 4 个子域，Web 前端层归并为运行与入口、界面与基础、业务功能、测试验证 4 个职责域；核心包层为 3 节点；后端核心层为 21 节点、76 条聚合依赖。每层子域控制在 6 个以内，父域收起后会恢复上一级节点，函数级源码阅读和原有模块选择器保持可用。
## 超大项目分批分析

针对 AIHOT 等源码范围较大的项目，AI 分析已从单批保护提示升级为受控分批流程：服务先按文件估算上下文，必要时按行范围切分；每批独立请求并校验函数归属、源码路径和模块证据，全部批次完成后合并模块与概览。分析进度会持久化为“已完成/总批次”，每批架构结果写入同一快照的检查点，页面实时显示当前批次；失败或中断后会从最后一个完整批次继续，并提供“重新开始分批分析”入口。

固定响应测试覆盖两批上下文的规划、逐批进度、失败恢复、用量合并和最终实体归属校验；接口测试进一步验证检查点文件在暂停后保留、重试时只发送未完成批次、成功后清理。随后在项目页面已有授权范围内，对 AIHOT 的固定快照完成了真实 DeepSeek 分批联调，结果见下方“AIHOT 真实联调结果”。

AIHOT 本地静态审计：快照纳入 444 个 TypeScript/TSX 源码文件，识别 1512 个可见函数、6557 个作用域和 25074 条调用记录，其中 4073 条为静态确认调用，未产生解析诊断；批次规划为 64 批，最大批次上下文约 150000 字符。该审计只读取快照并使用本地解析器，没有执行 AIHOT 源码或上传源码。

## 连线通道与间距优化（2026-10-10）

- 复现“路由集合 + 同级 app/http”场景：多个跨容器关系共用走线通道，部分末段连接不同端口时出现斜线。端口现在固定所在侧，由 ELK 优化次序；跨层输出斜段归一为直角折线。
- 为紧凑复合图增加节点和标题区避让，以独立网格通道布线。同来源扇出按端口顺序处理；禁止线段重叠，并为平行线路保留至少 18 个画布单位间距。转折保留圆角，交叉使用浅色间隔描边。关系 ID、真实端点和原始调用证据不变，SVG 复用相同走线。
- 初始显示、“适应画布”和窗口尺寸变化均为顶部标识、底部图例与侧边控件预留空间。图层视角使用新布局版本键，避免旧视角裁掉新布局端点。
- 自动检查：18 项前端测试、类型检查、生产构建通过。新增真实 ELK 的 8 节点、10 条关系回归场景，检查无斜线、无共线重叠、平行间距、卡片避让、确定性和 SVG 路径一致性。
- 浏览器按“应用服务 → API 服务 → 路由集合 → 显示其他模块”恢复用户场景；实际 DOM 中 10 条协作线均保留，直线段没有斜线，最小平行间距为 18。最终截图保存于本地 `output/playwright/依赖通道与间距优化.jpg`，侧边页面保留该场景。
