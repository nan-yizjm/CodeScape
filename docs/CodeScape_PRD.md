> **决策依据**：v1.0 原始决策记录（见附录 A）及本轮确认的产品方向；修订说明见附录 C

## 0. 阅读说明

- **P0**：第一版必须具备的范围。即使实现方法调整，也应满足相应用户体验与验收目标。
- **P1**：计划在后续版本实现；不纳入第一版交付验收。
- **已确认事实**：源码或静态工具可验证，或 AI 依据明确、可追溯的源码证据判断且目标无实质歧义；须在详情中标明证据来源。
- **分析不完整**：因语法、动态机制、条件编译、语言支持或服务异常而不能作出可信判断；不允许将缺口伪装成完整事实。
- **当前模块**：用户在语义架构图中进入并正在聚焦的逻辑模块。一个逻辑模块不一定对应一个文件夹。
- **源代码快照**：导入/分析时保存的、与分析结果匹配的只读代码副本；**不是**用户原始仓库。

需求编号 `FR-*` 用于开发追踪和测试；附录 A 保留原始第 1—122 项选择的对应关系。如条目曾被后续决策修订，以**最新明确决策**为准。v1.1 将本轮明确确认的方向与为消除歧义而补全的规则分别记录在附录 C；编写补全不冒充用户逐项确认。

## 1. 执行摘要

### 1.1 一句话定位

**CodeScape 是以交互式语义架构图帮助用户建立陌生项目整体认知，并支持逐层深入真实源码、持续记录学习进度的个人代码学习工具。**

### 1.2 要解决的问题

陌生代码仓库常有大量文件、复杂命名和跨模块协作。传统 IDE 更适合已知目标的代码搜索与编辑，直接阅读文件目录则难以快速建立“项目做什么—模块如何分工—函数如何调用—证据在哪里”的连贯认知。CodeScape 以**自然语言理解 + 结构化架构可视化 + 源码定位**形成学习闭环。

### 1.3 核心价值

1. **先理解整体**：自动生成项目目标、核心功能、工作原理与主要模块说明。
2. **循序进入细节**：语义缩放使用户从模块、子模块一路进入函数级调用图。
3. **不脱离源代码**：调用和模块关系具有来源记录，支持跳转到具体文件、行号及调用语句。
4. **准确性有边界**：静态分析和 AI 协作；不能可靠识别的内容必须暴露局限。
5. **持续学习**：记录探索位置、阅读位置和学习状态，支持下次接着学。

### 1.4 成功标准

用户可在不手动搭建被分析项目运行环境的前提下完成下列完整路径：

`启动应用 → 导入公开 Git 仓库/本地目录 → 了解分析范围并完成必要授权 → 分析 → 阅读中文项目概览 → 探索模块与关系 → 深入函数图 → 查看调用证据和源码 → 标记学习进度 → 关闭并恢复学习`。

第一版优先做到**可用、可解释、可追溯、可恢复、安全**，不承诺完全重建程序所有运行时行为。

### 1.5 产品目标优先级

- **首要目标：建立整体认知。** 用户先理解项目用途、核心能力、主要模块职责及模块之间的协作方式。
- **支持目标：自主深入学习。** 用户可以在整体认知基础上，自由深入模块、函数及源码，记录学习状态并跨会话继续。
- 两者是一条连续的探索路径，不要求用户先选择学习模式；不要求按固定顺序阅读或完成全部学习标记。
- P0 客观展示项目概览与架构，不提供推荐阅读顺序、起点推荐或学习路线；阅读指引列入 P1。
- 产品是否达到目标，除检查功能可操作外，还应通过代表性项目检查概览与架构能否帮助用户说明项目用途、主要模块分工和至少一条有证据的核心协作关系；不将探索时长或学习标记数量等同于理解程度。

## 2. 用户、场景与产品边界

### 2.1 目标用户

- 个人开发者与计算机相关专业学生；
- 希望系统学习 GitHub/GitLab 等公开开源仓库的人；
- 接手陌生项目、希望先理解整体模块分工与关键代码的人；
- 希望用架构视角而非逐文件浏览方式学习代码的人。

### 2.2 典型场景

| 编号 | 使用场景 | 目标结果 |
|---|---|---|
| US-01 | 第一次导入不熟悉的开源仓库 | 用通俗中文概览理解用途和主要模块 |
| US-02 | 想了解模块之间的协作 | 查看有向模块依赖、自然语言关系和证据 |
| US-03 | 想知道某模块如何实现 | 连续深入到本模块全部已识别函数及内部直接调用图 |
| US-04 | 对某条调用关系有疑问 | 展开证据、跳转到对应源码语句并返回 |
| US-05 | 分多天学习一个项目 | 保存学习状态、图上焦点、阅读位置，下次继续 |
| US-06 | 尝试不同扫描范围或重复导入同一仓库 | 每个导入记录独立，不覆盖其他学习记录 |
| US-07 | 项目分析很长或 AI 服务中断 | 停止、保存检查点、手动恢复，已完成版本仍能阅读 |

### 2.3 第一版边界

- 单机、单用户、以 Windows 10/11 为首发平台；使用本地服务 + 浏览器前端。
- 首批语言：**C/C++、Python、TypeScript**；不同语言和语法特性允许不同覆盖能力，必须标明局限。
- 公开 Git 远程仓库与本地源码目录；远程 Git 第一版只分析默认分支。
- 不承担代码编辑、调试、运行、编译、测试执行、多人协作、运行时全路径还原等职责。
- 复杂的程序行为视图、搜索、笔记、架构手动编辑以及版本比对等归入 P1。

## 3. 信息架构与使用流程

### 3.1 核心页面/区域

| 页面或区域 | 主要内容 | 进入方式 |
|---|---|---|
| 启动与基础配置 | 一键启动、AI 服务配置和连接测试、首次云端源码授权 | 首次启动/设置 |
| 项目学习库 | 项目列表、导入、打开、删除、手动重分析、学习进度和最近状态 | 默认入口 |
| 导入与扫描范围 | 源码来源、默认排除项、用户排除/包含调整 | 新建项目 |
| 分析任务区域 | 进度、状态、错误、Token/估算费用、队列操作、停止/恢复 | 导入后/任务管理 |
| 项目概览 | 项目用途、核心功能、整体原理和模块简介 | 分析成功后首次展示；架构图顶部可随时打开 |
| 语义架构主画布 | 模块层级、节点、依赖、平移缩放与语义展开 | 进入项目 |
| 统一右侧辅助区域 | 项目概览、模块/关系/函数详情、源码阅读 | 相关交互按需打开 |

### 3.2 首次导入主流程

1. 用户在项目学习库中选择“导入项目”。
2. 选择**本地目录**或填写**公开 Git URL**。
3. 系统读取来源信息，应用默认文件过滤规则，允许用户根据需要调整扫描范围。
4. 若 AI Key/Endpoint/模型尚未配置，先引导配置并测试；若尚未授权将源码发送到云端，先明确告知并取得授权。
5. 满足前置条件后自动创建分析任务：空闲则开始；已有任务运行则进入队列等待**用户主动启动**。
6. 展示分析状态，必要时显示失败原因、局部不可解析警告和恢复操作。
7. 分析成功后，首先展示自然语言项目概览；用户可进入架构图。
8. 当前图与只读源码快照绑定；支持学习状态与探索位置持久化。

**重要协调**：导入后的“自动启动”不覆盖等待队列“任务完成后不得自动启动下一项”的规则；首次源码上传授权也不因“不需要费用预确认”而省略。

### 3.3 再次打开/重新分析

- 打开已分析项目时加载最新成功版本，可离线查看，并恢复上次探索位置。
- 若有未完成分析任务，应用提示**恢复**或**暂不恢复**，不得静默产生新 AI 请求费用。
- 用户可手动发起重新分析。旧成功版本继续可读；新分析完整提交成功后再切换；失败时不覆盖旧版本。

### 3.4 页面交互基本原则

- 高层架构主画布优先，占据尽量完整的工作区域。
- 模块主体点击用于**进入/返回语义层级**；信息按钮用于打开详情；悬停预览不应触发层级跳转。
- 右侧区域按需出现，共用一个区域，不并排堆叠多个详情面板。
- 右侧切换内容不改变主画布的语义层级、视角或焦点。
- 点击关系证据可以跳转到源码，再返回关系详情及原阅读位置。

## 4. 项目来源、导入与项目库（P0）

### FR-IMP-01 项目导入来源

- 接受 Windows 本地源码目录。
- 接受公开 Git 仓库 URL（包括常见的 GitHub/GitLab 公共仓库）。
- 第一版不直接支持私有远程仓库的 SSH/账户凭证管理；用户可先自行克隆到本地。
- Git 导入自动解析远程**默认分支**，记录实际分析源码对应的 Commit ID，并保存快照；不提供分支、标签或指定 Commit 的选择入口。
- 重新分析远程仓库时，可获取默认分支的当时版本；不得让旧分析结果指向新的、不匹配的源码。

### FR-IMP-02 扫描与排除规则

- 默认排除 `.git`、`node_modules`、已知生成产物、编译构建目录、缓存及临时文件等。
- 用户可调整包含/排除范围，包括是否纳入测试及第三方源码。
- 应识别并尽量排除敏感文件与密钥；云端代码发送严格遵守用户授权及最终有效的分析范围。
- 被排除依赖在必要时可以作为**抽象的外部依赖信息**说明，不能伪装成已完成源码分析。
- 对大仓库提示规模风险并允许缩小扫描范围。

### FR-LIB-01 多项目管理

- 每次导入创建独立项目实体，允许同一 URL/目录多次导入。
- 同名时自动生成 `Name`、`Name (2)`、`Name (3)` 等名称；第一版无需自定义项目名。
- 在项目库显示项目名、来源、导入时间、学习进度/最近访问状态及分析状态。
- 项目间的源码快照、分析结果、任务、学习进度和浏览状态相互隔离。
- 支持项目切换、重新分析和删除；第一版不提供项目全文搜索。

### FR-LIB-02 删除项目与不可恢复性

- 删除前明确说明删除内容并二次确认，可取消。
- 仅删除软件自身管理的项目记录、分析数据、源码快照、学习状态、探索记录和关联任务；对运行中/排队中的该项目任务执行必要取消和清理。
- 第一版永久删除，无回收站和撤销功能。
- **任何情况下均不得删除用户的原始本地源码或远程仓库。**
- 删除出错时如实报告，不得错误提示成功；删除其他独立项目不受影响。

## 5. AI、静态分析与证据可信度（P0）

### FR-ANA-01 总体分析目标

在首次进入图形探索前，对所选源码尽可能完成：

1. 项目用途、核心功能、整体工作原理的中文概览。
2. 真实逻辑模块与可变深度的模块层级。
3. 模块职责、模块间已确认协作关系及其解释。
4. 项目自身真实函数实体、所在文件/位置、声明与定义映射。
5. 符合本 PRD 展示范围的已确认**直接**函数调用边及证据。
6. 未解析调用、被排除文件、支持局限与不完整模块的明确记录。

**分析尽可能前置计算，浏览阶段优先读取结果，不应每次点击模块都重新请求云端 AI。**

### FR-ANA-02 AI 角色

- AI 深度参与模块语义归纳、职责解释、模块分组、项目概览、问题诊断和有限重试/纠错。
- AI 可以辅助代码解析：当静态分析工具不能独立确定目标时，允许 AI 基于**具体调用位置、可定位的目标实现及充分代码上下文**判断某条直接调用关系。
- 对每条调用边区分来源，如 `静态分析确认` 与 `AI 基于源码判断`；第二类不得假称为前者。
- AI 有权给出自然语言总结，但不能凭空创造不存在的模块、函数或已确认调用；目标明显有歧义时须标为未解析。
- 源码位置可追溯是判断依据，不等同于结论自动正确。AI 判断必须能够说明调用位置、目标实现及二者对应依据；不使用模型自行给出的置信分数替代证据。
- 静态分析与 AI 对同一目标出现实质冲突且无法消除时，将该关系保留为未解析并在详情说明，不静默覆盖已有结论或绘制确定边。
- 模块解释可以采用通俗中文，但函数原名、类名、源码路径不可任意改写。

### FR-ANA-03 静态分析边界与执行安全

- **第一版严格静态分析**：只读取源码、声明、构建配置和已有编译元信息（如 `compile_commands.json`）。
- 不自动运行项目可执行文件、构建命令、安装脚本、测试命令或任意仓库自带脚本。
- 不要求项目在当前机器可成功编译。
- 遇到缺失编译参数、条件编译、虚调用、动态分派、复杂宏等情形，应保留局限性信息。
- 分析和修复过程均不得修改原始源码；内部重试和分析策略调整不得演变为执行未知项目代码。

### FR-ANA-04 语言支持和混合语言

- 首批支持 C/C++、Python、TypeScript；解析能力应有清晰的语言边界。
- 混合语言仓库作为**一个项目架构**呈现；对跨语言调用或接口关系，只在具备可追溯依据时建立依赖。
- 系统内部应保留源语言/文件/位置等信息；不支持部分使用占位或告警，不生成似是而非的关系。
- 语言扩展性是设计要求，但额外语言实现不属于第一版验收。

### FR-ANA-05 分析覆盖与不完整状态

- 部分文件解析失败不必导致整个项目全部失败：能保留可信的部分结果时应允许部分成功。
- 已知模块但无法准确分析时，以明显标注的不完整占位节点呈现。
- 函数存在无法解析的调用时，在函数级图中显示轻量“不完整/未解析”提示，但**不绘制猜测边**。
- 图中的缺失边只代表“未确认或未显示”，不得解释为“运行时绝不发生调用”。
- 所有结果需能回溯分析范围、源文件和适用源码版本。
- 分开表达**任务状态**与**结果覆盖情况**：任务完成不等于分析完整；已发布结果允许标记为“部分完成”，同时列出被排除、不支持、解析失败及未解析的范围或事项。不宣称未知部分已被穷尽识别。
- 可发布的最低结果应包含：与快照绑定的项目概览、至少一个有真实代码依据的可浏览模块、可定位的代码证据，以及范围和局限说明。不要求必须存在调用边，也不要求仅含顶层代码的项目必须有函数节点。
- 只有概览文本、没有可浏览且可追溯的架构结果时，不作为成功版本发布；保留诊断信息和可复用检查点。满足最低条件的部分结果可以发布，并明确展示缺口。
- 概览、模块图和函数图对同一缺口的说明应一致；不把“未显示”“被范围排除”“语言不支持”和“解析失败”混为同一种状态。

### FR-ANA-06 条件编译

- 尽可能识别 C/C++ 不同条件分支中的函数实现，即使它们不属于同一次编译。
- 对不同编译条件下的同名实现作区分；详情展示适用条件。
- 不能将互斥配置下的实现错误合并，亦不能跨互斥条件建立虚假的调用边。
- 对复杂宏、未知条件和无法可信判断的关系明确标记分析限制。

### FR-ANA-07 云端 AI 配置与隐私

- 用户自行配置 API Key、Endpoint、模型，支持连接测试。
- 需安全保存 API Key，界面不应随意明文暴露。
- 首次传送源码到云端前取得明确授权；告诉用户云端 AI 服务会接收选中范围内的相关代码。
- 不自动发送被排除的敏感文件；尽量只传必要片段。
- 第一版**必须配置 AI 服务**才能生成新的 AI 架构分析；已有结果的离线阅读不需要联网。
- 第一版不提供离线 AI 替代生成模式。

### FR-ANA-08 模型失败和费用处理

- 只使用用户指定模型，不擅自切换备选模型。
- 网络超时、限流等临时故障允许有限自动重试；持续失败则停止继续请求、暂停并保存检查点。
- 对无效密钥、不可用模型、上下文长度不足等提供明确错误说明和配置修复入口。
- 用户修改模型配置后可尝试从检查点恢复；避免无必要地重新付费执行已完成步骤。
- 记录分析过程实际 Token 用量并提供**估算费用**；价格信息不足时标明费用未知或仅供参考。
- **不要求分析前的 Token/费用预估或逐任务费用确认**，但首次云端代码上传授权仍必需。

## 6. 语义模块架构图（P0）

### FR-MAP-01 结构与层级

- 逻辑模块以**真实代码职责和帮助理解项目工作原理**为依据自动归纳；目录、包和类作为划分证据，不强制成为模块边界。
- 允许一个逻辑模块跨越多个目录，也允许同一文件内承担不同职责的函数归属不同模块；每个已展示函数在主层级中只有一个所属叶级模块。
- 对自身技术结构清晰的底层库、框架等项目，可以沿用其真实技术模块，不强行套用业务概念。
- 每个模块必须能追溯到对应的文件、函数或其他实际代码位置。不能仅凭项目名称、README 宣传或通用架构模板虚构实现模块；说明性文档可作辅助依据。
- 语义层级按真实项目动态生成，不要求固定“项目/系统/模块/子模块”等层数；没有意义的层级可跳过。
- 高层以简体中文模块名称及一句话职责说明为主；深入后逐渐使用更具体的代码实体名称。
- 每个模块在主层级中只有一个所属父模块；共享模块通过依赖边关联，不复制同一个实体。
- 同层模块过多时可按真实职责做语义聚合，但不可任意为了固定数量破坏模块含义。

### FR-MAP-02 语义缩放与画布操作

- 初始呈现项目主要逻辑模块及关系。
- 点击模块主体，画布平滑聚焦该模块并展示其子模块；其他同级节点默认淡出或隐藏。
- 提供查看其他同级模块的选项，开启后焦点模块合理缩小以容纳同级结构和跨模块依赖。
- 点击可见同级模块，可平滑转换焦点并展开它；点击当前展开模块可平滑退回父层级。
- 有明确的层级/面包屑导航；滚轮缩放与拖动画布仅改变**视觉视角**，不自动触发层级切换。
- 自动图形布局，尽量减少交叉和遮挡；P0 不提供持久化的手动节点拖放布局。

### FR-MAP-03 模块节点

- 节点显示简短模块名及一句话自然语言说明。
- 鼠标悬停显示轻量预览并突出直接关联模块/连线、淡化无关内容，鼠标移开恢复。
- 独立信息按钮打开右侧模块详情；主体点击用于展开或返回，不混淆交互职责。
- 模块详情展示概述、主要职责、所处位置、对应的实际代码范围和可用证据/可信度说明；不必把所有依赖细节塞进模块详情。
- 不完整模块在架构图上有足够明显的告警或缺失标识。

### FR-MAP-04 模块依赖边

- 模块依赖由具备依据的函数调用或明确接口使用/功能协作关系归纳而来，可聚合多条下层调用。
- 边具有明确方向；在模块层可有简短的自然语言关系名称。
- 默认优先展示主要依赖；支持切换到全部已确认依赖，告知当前是否隐藏部分连线及其数量（如可统计）。
- 点击依赖边打开统一右侧关系详情，架构图原状态不变。
- 详情说明模块之间如何配合、涉及哪些函数/代码位置、依据来源及未解析事项。
- 关系来源仅在打开详情后区分：标明 `静态分析确认`、`AI 基于源码判断`，或同一聚合关系同时包含两种来源。画布不因来源不同使用不同线型、颜色或来源徽标；不完整告警仍按既有规则展示。
- 聚合关系的每项证据保留自己的来源，不能将混合来源关系整体标成静态分析确认。对只有 AI 依据的协作解释，不表述为已经执行验证的运行时事实。
- **不单独因全局/共享变量、类继承、`#include`/`import` 创建模块依赖边**；导入、继承和共享变量等可以留在分析信息中。
- 仅有语法引用不等于已确认的运行时调用。对明确的跨语言接口关系须保留额外证据。

### FR-MAP-05 项目概览入口

- 分析完成首次进入项目时展示客观的自然语言概览，包含以下四部分：
  1. **项目简介**：项目解决的问题、主要使用对象或使用场景。
  2. **核心能力**：已从当前分析范围确认的主要功能，不把未来规划写成现有能力。
  3. **整体工作原理**：用有源码依据的说明串起模块协作，不假称还原全部运行路径或执行顺序。
  4. **主要模块职责**：与架构图一致的模块名称、职责及相互关系，避免重复堆砌目录名。
- 概览应说明当前分析范围与关键缺口；缩小扫描范围后，不把局部结论表述为对整个仓库的完整分析。
- P0 不增加推荐起点、建议阅读顺序或学习路线，用户自行选择探索方向。
- 架构图顶部提供随时重开“项目概览”的入口，在右侧统一辅助面板展示。
- 关闭概览后可恢复之前的详情/源码阅读状态，架构视角不丢失。
- 已保存概览支持离线浏览。

## 7. 函数级架构图（P0）

### FR-FUN-01 函数图范围

- 模块层级最终进入**函数级扁平视图**，不额外要求经过类/结构体层级。
- 展示当前模块内所有**已识别、具有实际实现、符合下列展示规则**的项目函数；不自动过滤成“关键函数子集”。
- 函数级图仅绘制当前模块内函数节点及它们之间的已确认直接调用边，不把其他模块或外部库函数加作节点。
- 函数节点默认仅用真实函数名；发生重载或同名冲突时补充类/命名空间/参数类型以区分。
- 函数所属类、结构体、文件、命名空间、完整签名等可以在详情中查看。
- 大图依靠自动布局与画布平移、视觉缩放探索；第一版不提供函数级悬停邻居高亮。

### FR-FUN-02 函数实体包含/排除规则

| 情形 | 函数级图 P0 规则 | 备注与准确性要求 |
|---|---|---|
| 普通函数、普通成员方法 | 展示 | 必须具备实际实现并属于分析范围 |
| 同名函数/重载函数 | 分别展示 | 使用必要的限定名/参数信息；内部实体标识唯一 |
| 声明 + 定义 | 合并为一个节点 | 点击优先到定义；详情保留声明位置 |
| 只有声明/纯虚/抽象/接口方法而无实现 | 不创建节点 | 不得将声明当成具体实现 |
| C++ 函数模板的不同普通实例化 | 合并为模板节点 | 保留实例化类型、调用位置；独立特化须区分 |
| 具有独立实现的显式特化 | 不错误并入普通模板实现 | 按实际独立实现定位 |
| C++ 运算符重载函数 | 展示 | 如 `operator+`、`operator[]`；符合条件的明确调用可成边 |
| C++ 构造函数、析构函数 | 不创建节点 | 仍分析其内部逻辑；不得归因给其他普通函数 |
| 函数式宏 | 不创建节点 | 宏使用不是普通函数调用；必要时用宏展开辅助识别真实调用 |
| Lambda、匿名函数 | 不单独展示 | 内部分析必须保留正确的调用主体归属 |
| Python 等具名嵌套局部函数 | 不单独展示 | 源码在外层函数中；不能把内部调用虚构为外层直接调用 |
| Python/TypeScript 模块顶层代码 | 不创建特殊节点 | 分析顶层初始化和调用，不能归为任意普通函数 |
| 标准库/第三方库函数 | 默认不创建节点 | 如果用户明确纳入相应依赖源码分析范围，按范围规则处理 |
| 全局变量/共享状态 | 不创建节点 | 可在函数详情保留读写/访问记录 |
| Python/TypeScript 异步函数 | 普通样式展示 | 不额外标 `async` 或绘制调度图 |
| `main()` 等程序入口 | 普通样式展示 | 不做专门入口标记（P1 可增加） |
| 条件编译不同分支的实现 | 尽可能区分展示 | 标示各自编译条件，不能错误合并互斥实现 |

> **展示与分析分离**：不显示某种节点，不代表放弃识别其作用域、源码、内部调用或对整体架构的影响。函数图不是源文件中全部可执行逻辑的清单；模块详情应说明重要但未单独成节点的实现位置，并允许通过源码位置阅读。P0 延续上述包含/排除规则，不通过把隐藏作用域内的调用挪给可见函数来弥补显示缺口。

### FR-FUN-03 直接调用边

- 函数级边以**有向箭头**表达直接调用；不重复添加“调用”文字标签。
- 与模块依赖边一致，函数调用边的判定来源仅在关系详情中区分，不在画布上按静态分析或 AI 判断使用不同视觉样式。
- 同一调用方 → 被调用方之间即使有多处直接调用，也只画**一条有向边**，但保留每一处已识别调用证据。
- 直接递归用指向自身的**自环箭头**，不为同一函数重复创建节点。
- `A → B` 和 `B → A` 分别为两条关系，不得合并。
- 无法确定目标的虚调用、动态调用不绘制猜测边，函数旁可提示存在未解析调用。
- 第一版**不绘制函数指针/回调等间接调用关系**，即使底层分析可记录其可能目标。
- Python 的 `@decorator` 应用不画为“被装饰函数直接调用装饰器”的函数边；真实函数体调用按规则分析。
- 能确定真实目标的运算符重载表达式可按照直接调用建边，但不得对重载解析不明的表达式擅自推断。
- 函数图仅表达经过判定的直接调用，不等同完整运行时调用图。

### FR-FUN-04 跨模块与外部库调用提示

- 当前函数图不引入外部模块函数或第三方库函数节点。
- 若函数存在**已识别的跨模块调用**，节点旁显示一个轻量存在性标记；**不显示数量，不需要点击**。
- 没有已识别跨模块调用时不显示该标记，但不意味着运行时绝无外部调用。
- 跨模块调用证据主要从上层模块依赖连线及其关系详情查看。
- 不将标准库/第三方库函数调用错误识别为项目内部函数调用。

### FR-FUN-05 函数详情

应按可用信息显示：

- 函数真实名称、签名、所属文件、源码位置；
- 类/结构体/命名空间归属、适用编译条件；
- 一句话/详细功能解释（用户通过信息入口主动查看，而不是节点自动展示）；
- 未解析调用提示及原因；
- 可识别的外部 API 使用或共享变量访问记录；
- 已识别声明、定义、模板实例/特化等信息；
- 与函数相关的证据来源：静态工具与 AI 判断必须区别显示。

## 8. 统一右侧辅助面板与源码阅读（P0）

### FR-UI-01 按需分栏

- 初始进入架构探索时，主画布占用主要工作区域；右侧辅助面板默认关闭。
- 点击具体函数时自动打开右侧**源码阅读器**，画布平滑缩到左侧。
- 模块概览、模块详情、依赖关系、函数详情、源码等共用同一个右侧区域，不允许第一版同时开多个并列面板。
- 可拖动分隔位置调整宽度；关闭后画布恢复空间。
- 从源码切换到关系详情或概览，再关闭临时面板时，可以恢复之前的内容及阅读位置。

### FR-SRC-01 源码阅读

- 只读展示**完整源文件**，包含文件名、相对路径、行号、语法高亮。
- 点击函数节点时优先定位到函数定义并高亮；用户可自由滚动。
- 一次只允许一个活动源码文件；第一版不提供多标签页与独立文件目录树。
- 第一版不提供编辑、源码内点击定义/引用查询或从源码反向跳转架构节点等 IDE 能力。
- 展示的是与当前分析结果**同版本**的只读快照，不能悄悄替换为已变化的原始项目文件。

### FR-SRC-02 关系详情与证据跳转

- 点击函数级调用边或上层模块依赖边，可查看相应关系详情和证据来源。
- 每处已展示调用证据必须包含源码版本标识、相对文件路径、可定位的行号或范围、对应源码片段与判定来源；支持点击位置进入源码阅读器并高亮相关调用语句。版本标识可以通过所属分析版本统一管理，不必在界面中重复铺陈。
- 非函数调用形成的模块协作关系也需给出实际代码位置和关系说明，并在详情标明证据类型，不能伪装成函数直接调用。
- 进入源码后支持返回之前的关系详情，尽量恢复其滚动/展开状态。
- 对同一对函数具有大量调用位置的关系，详情**默认折叠**：显示前几条与总数，提供“展开全部/收起”，全部位置均可点击。
- 任何面板切换或源码跳转不改变左侧画布原有语义层级、焦点或缩放/平移状态。

## 9. 学习进度与会话恢复（P0）

### FR-LEARN-01 学习状态

- 叶级可学习实体由用户手动标记：`未开始`、`学习中`、`已掌握`。
- 有可展示函数的叶级模块，以函数作为可学习实体；没有可展示函数但有可信职责说明及可阅读源码的叶级模块，以模块本身作为可学习实体，避免无法记录顶层代码等内容的学习状态。
- 仅表示未知范围的不完整占位节点不参与掌握率计算，也不允许标为已掌握；其分析缺口始终单独提示。不能因已识别部分全部掌握就宣称未知部分也已掌握。
- 父模块自动从直接子节点中可学习实体或可汇总模块的状态汇总：**全部未开始 → 未开始；全部已掌握 → 已掌握；其他 → 学习中**；递归向上汇总。没有可汇总子节点且本身不可学习时，状态为“不适用”，不能因空集合默认视为已掌握。
- 项目库的学习进度采用“已掌握叶级实体数 / 全部可学习叶级实体数”，不按函数长度加权，也不把“学习中”折算成任意百分比；分母为零时展示“暂无可统计学习内容”。
- 学习进度仅反映当前已发布版本中可学习内容的用户标记，不代表代码分析覆盖率或客观知识测试成绩；有分析缺口时并列提示。切换视图、隐藏连线或隐藏状态图标不改变统计口径。
- 架构节点可以显示状态图标，并支持统一显示/隐藏；不自动推断用户已掌握。
- 第一版不提供附着在节点上的个人笔记，也不生成强制学习路线。

### FR-LEARN-02 恢复探索状态

每项目分别保存：

- 当前模块、展开层级及面包屑位置；
- 画布视角、缩放及平移状态；
- 最近的右侧面板类型；
- 当前源码文件、选中函数、阅读滚动位置；
- 叶级学习状态、派生的父级状态与最近探索上下文。

再次打开项目时能够继续此前学习；离线时可恢复已保存的项目状态。

## 10. 分析任务调度、进度和版本（P0）

### FR-TASK-01 任务状态和进度

- 提供简单、易懂的分析状态：等待、分析中、暂停、失败、完成、已取消。已完成任务另行展示结果覆盖情况，不用“完成”掩盖部分分析。
- “暂停”保留有效检查点，可由用户恢复；“取消”终止当前任务且不再自动执行，不影响已有成功版本；“失败”显示原因及可用的重试或配置修复入口。恢复、重试均需用户主动发起。
- 能合理计算时显示进度百分比；不制造没有根据的百分比。
- 展示关键错误、重试和任务停止操作；不要求暴露所有底层技术阶段。
- 分析长时间运行时提供检查点，支持中断恢复。

### FR-TASK-02 单任务执行与队列

- 全局最多一个正在运行的分析任务。
- 其余分析任务进入持久化等待队列；用户可选择任意待执行任务、调整顺序、从队列移除。
- **任务完成后不自动启动下一任务**，需要用户主动启动，避免意外成本。
- 已有成功分析结果的项目在其他项目分析期间仍可正常浏览。

### FR-TASK-03 手动重新分析与版本一致性

- 第一版只支持**手动**触发重新分析，不自动侦测源代码更新并启动分析。
- 重新分析在独立任务中进行；正在浏览的旧有效图与对应源码快照继续保持可用。
- 新分析成功后，整体、原子地切换新的结果及匹配快照；分析失败保留旧版本。
- 按稳定实体身份迁移学习进度：能够可靠匹配且实现内容未发生变化的实体保留标记；新增、匹配不确定或实现发生变化的实体恢复为“未开始”，不继承旧版的“已掌握”。父模块按新版子节点重新汇总。
- 版本切换后提示学习状态的保留和重置情况。探索位置优先恢复到能够可靠匹配的实体；原实体不存在时回到最近可定位的父模块，无法定位则回到项目顶层，不跳到无关的同名函数。
- 每个学习项目只保留最新成功分析版本及对应快照（进行中的工作结果/检查点除外）；历史版本对比属于 P1。

### FR-TASK-04 启动时未完成任务处理

- 重新启动应用发现未完成任务时，提示用户选择恢复或暂不恢复。
- 用户没有明确选择恢复前，不得自动继续消耗 AI 请求。
- 失败恢复时复用有效检查点并保持旧成功结果安全。
- 恢复始终针对任务创建时的快照与扫描范围，不在恢复过程中静默读取更新后的原始源码。用户希望分析新源码或改变范围时，创建新的重分析任务。
- 修改 AI 配置后只重做无效或未完成的阶段；记录各阶段实际使用的模型和来源，不把多个模型生成的结果假称为单一模型输出。向新 Endpoint 发送源码前，需确认原有授权是否覆盖该接收方，不覆盖时重新取得授权。

## 11. 本地数据、安全与离线（P0）

### FR-DATA-01 本地存储与快照

- 分析结果、模块图、函数实体与调用证据、学习状态、任务/队列状态和源码快照都存储在本地。
- 源码快照从有效分析范围生成，需与 Git Commit/本地导入时的版本一致；禁止凭分析后原文件路径临时读到不同版本。
- 已分析项目离线可打开概览、图形、关系详情、源码快照并编辑学习状态。
- 第一版无账号、无云端同步；备份/导入导出完整项目数据和跨设备迁移属于 P1。
- 数据应与应用程序安装文件分离，避免应用更新或卸载动作不明原因地损坏学习记录。

### FR-SEC-01 源码、隐私与服务边界

- 未经用户明确授权，不发送源码到云端 AI。
- 配置密钥需要安全处理；错误日志、进度展示和导出内容避免暴露敏感信息。
- 本地服务仅监听 `127.0.0.1`，采取适当的本地 API 访问保护与请求校验。
- 默认以只读方式访问原仓库；不得自动执行未知程序/脚本或修改原始源码。
- 删除项目只删除软件管理的数据；不能触及原始文件夹/远程仓库。
- 快照、分析结果及云端请求范围需持续遵循用户的包含/排除设置。

### FR-SEC-02 本地服务生命周期

- 第一版提供 Windows 安装器和一键启动入口，用户不应需要手动安装独立 Python/Node 环境。
- 启动本地服务并打开浏览器页面，避免同一实例重复启动服务。
- 不长期驻留系统托盘；关闭全部学习界面后可自动停止服务。
- 鉴于浏览器关闭检测可能不可靠，应有连接检测与合理的缓冲/超时机制，不能因关闭一个标签页而误伤仍在使用的其他标签页。
- 退出前妥善保存学习状态、检查点及任务状态。
- 全部界面关闭且缓冲期结束后，正在分析的任务停止调度新请求，保存有效检查点并暂停，再退出服务；重新打开时按 FR-TASK-04 提示恢复。已经提交的云端请求可能产生用量，不能承诺关闭界面即撤销远端费用。

## 12. 交互视觉与导出（P0）

### FR-VIS-01 图形清晰度

- 模块图允许根据真实语义聚合层级；函数图必须包含当前模块所有已识别、符合展示规则的函数，不做“只展示核心函数”的默认过滤。
- 各图采用自动布局，视觉缩放和平移响应平顺；无硬性 FPS/毫秒验收门槛，但需避免明显阻塞。
- 关系边方向清楚，不重叠成不可辨认的大片连线；图形复杂时可提示阅读成本，但不能静默丢失已确认函数。
- 模块图有悬停邻居高亮；函数图第一版不做悬停邻居高亮。

### FR-EXP-01 导出当前视图 SVG

- 用户可导出**当前可见架构图**为静态 SVG；“当前可见”指当前语义层级和显示选项下的图形内容，包含因平移而暂时位于屏幕外的节点，不只截取屏幕矩形区域。
- 导出内容反映当前层级、当前可见节点、节点名称/模块简述、可见依赖或调用连线。
- 不要求在导出的 SVG 内保留点击、缩放展开或右侧详情面板互动能力。

## 14. 错误和边界场景处理

| 场景 | 必须呈现的行为 | 不允许的行为 |
|---|---|---|
| 无效/私有 Git URL | 给出可理解错误；提示可先本地克隆 | 冒充导入成功 |
| API Key 缺失或错误 | 引导配置/修复，保留项目和已完成任务信息 | 在无有效配置时伪造 AI 分析结果 |
| 尚未授权云端传输源码 | 明确请求授权并阻止源码发送 | 默认上传所有文件 |
| AI 限流或超时 | 有限重试，持续失败则暂停并记录检查点 | 无限重试/自动切换模型 |
| 部分源文件不支持 | 输出可信的部分分析和明显不完整提示 | 以推测填充全部缺口 |
| 不确定动态调用 | 保留未解析记录，不画确定边 | 猜出目标并当作工具验证结果 |
| 存在互斥条件编译实现 | 保留条件标注和实体区别 | 将互斥实现合并为同一函数实体 |
| 同一调用多处源码证据 | 只画一条边，详情默认折叠，支持展开与跳转 | 丢掉调用位置或重复铺满平行连线 |
| 原始目录被移动/更新 | 旧成功图仍绑定自己的源码快照 | 跳到新版本相同行号而不提示 |
| 重新分析中断/失败 | 旧版本继续可读、任务可按检查点恢复 | 半成品覆盖已成功结果 |
| 删除项目 | 二次确认，清理软件保存的数据及任务 | 删除本地原始仓库或其他导入副本 |
| 关闭一个浏览器标签页 | 保留其他活动窗口和必要的保存状态 | 直接终止其他用户会话中的服务 |
| 费用价格信息不可得 | 展示已知 Token，费用标为未知/仅供参考 | 编造精确费用 |
| 巨型源码仓库 | 提示限制、允许缩小范围；保留已确认结果 | 承诺无条件完整即时分析 |

| AC-26 | 删除 | 删除重复导入中的其中一个项目 | 仅该软件项目记录清理，原始源码及另一个项目无损 |
| AC-27 | SVG 导出 | 在任意已生成图中导出 | 文件可查看，内容与当前可见节点/连线基本一致 |
| AC-28 | 部分分析 | 导入混合语言或解析不全项目 | 满足 FR-ANA-05 最低条件的可信结果可发布，未解析区域/调用有明确提示；仅有概览不视为成功版本 |
| AC-29 | 整体认知 | 使用预先人工核对主要职责与协作的代表性仓库，阅读概览并探索顶层模块 | 可说明项目用途、主要模块分工和至少一条有证据的核心协作关系；与核对结果无实质矛盾，不用有无推荐路线作为通过条件 |
| AC-30 | 职责与代码映射 | 使用职责跨目录、同文件包含不同职责的样例 | 模块划分有代码依据，函数归属唯一，详情能定位对应代码；不强制照搬目录树 |
| AC-31 | 概览范围与边界 | 分别分析完整范围和缩小范围的同一仓库 | 概览包含约定四部分，与当前架构一致，说明范围缺口，不生成阅读顺序或推荐起点 |
| AC-32 | 学习统计边界 | 测试无函数但有可读源码的模块、不完整占位及零分母情况 | 叶级对象和分母符合规则，占位不被算作已掌握，不把学习进度当作分析覆盖率 |
| AC-33 | 重分析状态迁移 | 分别保留、修改、新增、删除函数后重分析 | 仅可靠匹配且实现未变的实体继承状态，其余重置并提示；失效探索位置安全回退 |
| AC-34 | 检查点一致性 | 暂停后修改原仓库，再恢复任务 | 恢复仍使用原任务快照及范围；分析更新内容需要新的重分析任务 |
| AC-35 | 判断冲突 | 构造静态分析与 AI 判断无法协调的目标冲突 | 不画确定边、不静默覆盖，记录未解析事项及冲突原因 |
| AC-36 | 服务退出与恢复 | 分析过程中关闭最后一个界面，再重新打开应用 | 缓冲期后保存检查点并暂停退出；重开后需主动恢复，仍有其他活动标签页时不误停 |

### 15.1 验收样本与质量口径

- 开发前选定并固定版本的一组代表性仓库，至少覆盖三类首批语言、小型项目、职责跨目录的中型项目，以及存在局部不支持内容的混合语言项目；同一仓库可以覆盖多个场景。
- 为样本记录有效扫描范围、源码版本、主要模块职责和可核对的核心协作证据，用于验证整体认知目标；不要求 AI 输出固定模块名称或唯一层级树。
- 重载、条件编译、递归、匿名作用域等边界可使用小型人工样例验收，不将单个大仓库的表现替代全部语言规则检查。
- 记录代表性项目的分析耗时、Token 用量和图形可读性，作为首版支持范围说明的依据；不新增统一算法准确率、固定时长或 FPS 门槛。
- 部分成功属于正常交付形态，但不得通过减少可见内容、把有歧义结论列为已确认或隐瞒缺口来满足验收。

## 16. P1 后续路线（不纳入第一版交付）

### 16.1 学习与搜索

- 项目内按名称/语义搜索、跨图快速定位。
- 面向模块或函数的用户学习笔记。
- 架构阅读指引（建议先关注的模块及理由）、推荐学习路线、关键入口导航与程序入口标记。
- 用户主动请求的 AI 代码解释。
- 双项目同屏对比学习：在同一屏幕并排探索两个项目，比较架构与实现，详见 16.5。

### 16.2 更深层分析

- 结构图与行为图双视图、执行场景、运行流程和时间顺序。
- 函数内部控制流/算法/数据流可视化。
- 更完整的间接/动态调用分析与呈现。
- 更丰富的调用关系类型与数据依赖图（并非默认混入 P0 直接调用图）。
- 量化结构准确性评估、严格性能指标、大型仓库专项优化。

### 16.3 项目管理与可编辑性

- 手动编辑架构：模块改名、拆分、合并、修正依赖及其变更历史。
- 重新分析后合并用户人工修改。
- 自动识别源码更新并提示重分析。
- 项目回收站、误删恢复。
- 多分析历史版本和差异比较。
- 完整备份、迁移、跨设备同步、多用户与云端账号。

### 16.4 导入与平台

- Git 远程分支/Tag/指定 Commit 选择。
- 私有远程 Git 仓库认证（含 SSH 凭据）。
- Linux/macOS 正式安装支持。
- 局域网访问、托盘常驻或更复杂生命周期管理。
- 可交互 SVG 导出。
- 函数级悬停高亮；源码内跳转定义/引用、多标签文件阅读。

### 16.5 双项目同屏对比学习

- **目标**：用户可以在同一屏幕同时查看两个项目，方便比较它们的模块分工、协作方式及具体实现，减少反复切换项目的操作。
- **基本方式**：从项目学习库选择两个已有分析结果的项目，进入左右并排的对比视图；两侧明确显示项目名称与来源，可调整区域宽度。
- **独立探索**：两侧分别支持查看项目概览、探索模块架构、深入函数及阅读源码；各自保留层级、视角与阅读位置，操作一侧不改变另一侧的探索状态。
- **数据归属**：学习状态、源码快照和关系证据仍分别归属各自项目，不能因对比展示混用源码或学习记录。
- **范围**：基础能力为用户自主对照阅读；自动匹配模块、联动导航、代码差异高亮和 AI 比较总结可后续单独评估，不作为本项基础要求。
- **交付阶段**：P1，不影响 P0 的单项目主画布与统一右侧辅助面板设计。对比模式下各侧详情与源码的具体布局在后续设计中确定。
- **后续验收方向**：能同时打开两个项目并分别深入不同层级、查看各自源码；操作与学习标记互不干扰，项目身份和证据归属清晰。

## 17. 一致性与关键取舍记录

### 17.1 关于“只展示已确认调用”与“允许 AI 确认”

第 93 项要求不画未确认目标的猜测边；第 119 项进一步允许 AI 在有明确源码证据时判定直接调用目标。两者不冲突：**AI 判断可作为确认渠道，但必须可追溯、来源明确、没有实质歧义**。不能用“AI 认为大概如此”取代源码证据。来源仅在点开详情后区分，模块边和函数边均不因判断来源使用不同视觉样式；不完整提示仍保留。

### 17.2 关于“函数级只有直接调用”与“模块级语义依赖”

函数级视图只绘制确定的当前模块内部直接调用；模块图可以由多条已确认调用或明确接口协作关系聚合形成。模块图不等同简单函数边复制，也不应因导入、继承或共享状态自动连线。

### 17.3 关于“完整函数图”与“省略部分代码结构”

“全部函数”专指当前分析范围内，符合 FR-FUN-02 规则、已识别且具有实现的函数。宏、构造/析构、Lambda、嵌套局部函数、模块顶层代码等按已定规则不单独可视化，不代表分析时可以忽略或错归属。

### 17.4 关于云端授权、费用与自动分析

第 58 项选择导入后自动分析；第 120 项选择不事先估价确认；第 30 项要求首次上传源码明确授权；第 75 项要求队列不自动连续执行。因此：**满足 AI 配置和授权时新导入可自动开始；如有正在运行任务则排队且须用户主动启动；无需事前费用预估，但不允许绕过源码上传授权。**

### 17.5 关于历史版本与源码正确性

保存最新**成功**分析版本不等于可在重新分析失败时删去旧版本。新版本完成并能够对应新的快照后方可原子切换；旧图与旧源码始终一一对应直到切换。

### 17.6 关于项目删除

删除的是 CodeScape 本地管理数据，不是被分析项目本身。用户重复导入相同仓库生成多个学习项目时，删除其中一个绝不应影响其他导入记录与原始仓库。

### 17.7 关于构建信息

可**读取** `compile_commands.json`、CMake 等配置，不能据此自行运行 CMake、编译器、构建脚本或安装依赖。不能根据“需要编译信息”推导出用户已授权执行代码。

## 18. 实现前的待验证技术风险（非新增产品需求）

| 风险 | 对产品的影响 | 技术设计阶段需验证 |
|---|---|---|
| AI 生成的语义模块是否稳定、可复现 | 重新分析可能导致层级和学习状态映射困难 | 模块身份、证据保存、版本比较与迁移策略 |
| C/C++ 构建配置不完整 | 函数解析与条件编译精度受限 | 静态工具在不运行项目下的支持边界 |
| 多语言混合与动态机制 | 可能存在无法可靠确定的接口/调用 | 统一实体模型、分语言解析能力说明及降级策略 |
| AI 对调用目标的判断不稳定 | 错误调用边会伤害产品可信度 | 证据数据结构、来源标注、保守准入规则与抽样评测 |
| 大型函数调用图布局拥挤 | 完整展示可能影响流畅性和可读性 | 图形渲染、布局计算及大图性能策略 |
| 源码上传与敏感信息 | 隐私风险 | 文件过滤、传输边界、凭据加密、错误日志脱敏 |
| 快照与重分析原子切换 | 行号错位或损坏历史阅读体验 | 版本标识、快照不可变性、事务提交/回滚 |
| 浏览器关闭与本地服务退出 | 状态丢失或误停 | 活跃连接检测、状态写回和宽限期 |

这些是后续**技术方案需要解决的问题**；本 PRD 不预先指定必须使用某种解析器、框架、数据库或图引擎。
