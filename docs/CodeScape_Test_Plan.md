# CodeScape 测试与验收计划

版本：v1.0  
日期：2026-10-09  
对应文档：[开发设计](CodeScape_Development_Design.md)、[PRD v1.1](CodeScape_PRD.md)。

本计划规定测试输入、预期结果、需求追踪和发布证据。表中均为待实施测试，不表示已有通过记录。人工样例由 AI 编写，用户可按可读步骤验收；样例目标代码只作静态输入，不运行其构建或测试。

## 1 分层验证

| 层次 | 工具/方法 | 验证内容 |
|---|---|---|
| 静态与领域单元 | pytest | 实体归属、调用准入、指纹、统计、状态机和路径约束 |
| 前端单元 | Vitest | 语义/视角分离、面板返回、状态统计和 SVG 数据转换 |
| 契约 | Pydantic/JSON Schema/OpenAPI 类型生成检查 | 版本、枚举、DTO、无效模型输出和接口错误 |
| 集成 | 临时数据库与快照、故障注入、模拟 provider | 检查点、事务、队列、发布、取消和删除 |
| 浏览器 | Playwright | 实际前后端交互、源码高亮、图导航、离线与多标签页 |
| 真实 AI | 用户已配置和授权的 DeepSeek；兼容服务选定后单列 | 语义模块、中文概览、有限复核、证据可读性与用量 |
| 安装交付 | 当前目标 Windows 11 x64 开发机；CHG-13 免除干净矩阵 | 无开发运行时条件下安装、启动、升级、卸载 |

模拟 provider 用固定响应保证测试可复现；不得据此宣称 DeepSeek 或其他服务已经兼容。实际端点测试记录模型、接收方、参数、提示词版本、用量与运行日期，不记录 Key。单次成功不能证明模型稳定性，代表性样本至少重复分析并检查不变量；不要求模块名称和树形完全一致。

## 2 固定样本与人工基线

真实仓库取 [benchmark_sources.json](benchmark_sources.json) 中固定 Commit，不随默认分支自动漂移。M0 抓取后验证初始路径规则，生成排序文件清单、逐文件哈希、整体范围哈希及排除理由；若初始路径不匹配，明确更新清单与设计记录，不用空输入跑出通过。

每个仓库建立人工核对 baseline，含项目用途、主要职责、至少一条可证实核心协作、源码定位和已知边界。baseline 不固定 AI 模块中文名称或唯一树结构，也不能只由同一个待测模型输出即视为人工核对。

| 样本 | 用途 | 重点 |
|---|---|---|
| Hiredis | 首条完整产品路径 | 同步/异步接口和解析职责，函数指针不误画 |
| spdlog | C++ 真实工程 | 头文件实现、模板、成员方法、条件与缺依赖说明 |
| Flask | Python 语义架构 | 框架职责、装饰器和动态机制保守处理 |
| Zod | TypeScript 工程 | 类型与实现、符号解析、匿名作用域与多目录职责 |
| mix-boundary 人工项目 | 混合语言与部分支持 | Python、C++、TS 和不支持语法/语言；证据足够的桥接及只有同名的反例 |
| responsibility-split 人工项目 | 真实职责而非目录树 | 一项职责跨两个目录，一个文件包含两项职责；函数归属唯一 |

规模以实际 manifest 中有效文件和代码量报告，不能凭仓库知名度称为中型。若四个核心范围不足以覆盖中型场景，M0 扩展同一固定仓库的业务源码范围并另存 manifest；不得引入依赖产物虚增规模。

## 3 人工规则样例

| ID | 输入设计 | 必须满足 |
|---|---|---|
| FX-01 basic-calls | A 调 B 两次、B 调 A、A 自递归、未被调用的 C | 3 个节点；A→B 一边两证据；B→A 独立；A 自环；C 不被过滤 |
| FX-02 identity | 声明/定义分离、重载、同名不同命名空间 | 声明定义合并；重载和同名实现不误合并；定位定义 |
| FX-03 templates | 普通模板实例、独立显式特化 | 普通实例合并；特化独立；证据保留类型 |
| FX-04 hidden-scope | 外层函数中 Lambda、具名局部函数；类构造析构；顶层执行代码 | 隐藏结构不独立成节点；内部调用不转移到外层函数；模块可读源码 |
| FX-05 conditions | #if FEATURE / #else 下同名不同实现与跨互斥引用 | 条件实现分开；不生成互斥调用边；未知条件有诊断 |
| FX-06 dynamic | 函数指针、回调、虚分派、Python 动态属性、TS 联合类型方法 | 不确定或间接关系不画确定函数边；不能以同名猜测 |
| FX-07 decorators | 装饰器替换函数；函数体内真实直接调用 | 装饰器应用不伪装普通调用；被替换目标保持不确定 |
| FX-08 operators | 可唯一解析与有歧义的 C++ operator 表达式 | 真实重载函数可见；仅前者成边 |
| FX-09 no-edge | 只有 import/include、继承、共享变量访问 | 不据此单独连模块依赖 |
| FX-10 mixed-bridge | 调用端接口、明确绑定注册、目标实现；另有同名无绑定项 | 双侧证据齐备才有跨语言协作；同名反例无确定关系 |
| FX-11 positions | CRLF、中文、emoji、tabs、多行调用、宏 spelling/expansion | 行列和片段与快照一致，点击高亮准确 |
| FX-12 learning | 有函数叶模块、纯顶层模块、未知占位、空项目 | 分母与父汇总符合规则，零分母不显示 100% |
| FX-13 migration | 仅注释排版、改签名/实现、新增、删除、移动、同名歧义、改宏条件 | 只可靠且指纹相同者继承；其余重置；docstring/语义换行不能误忽略 |
| FX-14 unsafe | 恶意脚本、编译参数插件、response file、symlink/junction、路径穿越、秘密文件 | 不执行/越界/上传；原目录哈希不变；记录原因 |
| FX-15 ai-invalid | 不存在实体、伪行号、循环模块、重复归属、无限补读请求、空/截断 JSON | 拒绝错误产物；有限重试；结构不合法不能发布 |
| FX-16 conflict | 静态目标 A、AI 目标 B 且无法消除歧义 | 两份依据保留，确定图无该边，诊断明确 |
| FX-17 graphs | 50/200/1000 节点，稀疏/密集、自环、双向边、长中文名 | 不静默少节点；测布局与交互，SVG 含离屏节点；不设置未经确认的 FPS 门槛 |
| FX-18 lifecycle | 两标签、刷新、后台节流、休眠唤醒、最后标签关闭 | 非最后关闭不误停；宽限、暂停与主动恢复正确 |

FX-17 的规模是测试梯度，不是已承诺流畅支持的上限。若 1000 节点测试暴露问题，记录并改进或说明阅读成本，不能默认只显示前 200 个函数。

## 7 故障注入清单

1. 响应发送前、发送后但未收响应、已收响应未落盘、已落盘未登记检查点分别中断；检查复用与 outcome_unknown，不声明远端未收费。
2. 快照复制中、prepared 后、发布事务前、事务后但广播前、旧版本清理中强制退出；检查 current 与快照始终一致。
3. 发布映射计算期间另一个标签修改学习状态；最终事务必须迁移最新已提交标记，旧版本后续写入返回 VERSION_CHANGED。
4. 暂停与取消同时到达、重复点击开始、两项目同时 start、任务完成与新导入同时发生；最多一个 running，等待队列不自动消费。
5. 关闭一个标签、全部标签、后台节流、系统休眠、SSE 中断、端口被占和旧锁文件；不能启动重复服务或误认为旧 PID 必然有效。
6. 磁盘不足、只读目录、SQLite busy、快照缺失、数据迁移失败、文件占用删除失败；错误真实可见，不清空学习库。
7. CSRF、错误 Origin/Host、未交换 nonce、重复兑换 nonce、file_id 属于另一项目、路径穿越与 junction；一律拒绝越界读取或操作。
8. 模型生成伪实体、外部路径、恶意 HTML、提示注入、循环工具请求；拒绝越权，且重试总次数有限。

## 8 用户验收流程

每个可运行版本提供一页“本轮验收”，说明使用样本、操作步骤、预期结果、已知缺口和结果记录位置。最终验收按以下顺序：

1. 在本轮目标 Windows 环境安装，点击快捷方式，确认浏览器自动打开；再次启动不出现第二服务。
2. 配置 DeepSeek，执行无源码连接测试；首次授权前确认界面说明接收方与传输范围。
3. 导入 Hiredis，查看范围后分析；检查阶段、用量和暂停恢复，等待完成后阅读四部分概览。
4. 用自己的话说明项目用途、主要职责和一条核心协作，再点击该关系核对源码依据。
5. 进入函数层，检查真实名称、自环/多证据样例，打开完整源码并返回；面板变化不能丢失画布焦点。
6. 标记几个叶级状态，关闭重开、断网重开，确认位置和标记恢复；检查零分母与不完整模块样例。
7. 同时导入多个项目，主动选择任务；前项完成后下一项保持等待。
8. 在旧结果打开时重分析并模拟失败；旧代码继续可读。成功切换时显示学习状态保留/重置情况。
9. 将部分节点平移出屏幕后导出 SVG，打开文件，确认完整当前层级仍在。
10. 重复导入后删除其中一项，验证另一项和原目录完整；检查取消删除和删除失败提示。
11. 按规则样例核对 C++、Python、TypeScript、混合语言和职责跨目录情况。
12. 完成升级/卸载测试，确认数据保留选项明确，原始源码不受影响。

用户不需要人工审阅每条数据库记录；开发方提供可定位证据、自动测试报告和关键反例。若只能展示好看的图而无法核对关系或解释缺口，验收不通过。

## 9 报告格式与发布门槛

每次测试记录：build_id、设计/PRD 版本、OS/浏览器、依赖锁哈希、样本 Commit、scope_hash、模型配置及提示词版本、测试 ID、expected、actual、pass/fail/blocked、证据路径、缺陷编号。没有执行记录不得写 pass。

阶段报告目录约定为 `docs/reports/<build_id>/`，含 machine-readable results.json、简短人工报告、必要截图或 SVG、用量摘要。真实源码和 Key 不附入通用日志。本文未预填通过结果。

发布阻断项：原源码损坏/越界删除、未授权上传、错误版本源码、确定假边、错误作用域归属、函数被静默丢弃、等待任务自动收费、成功版本被失败覆盖、已完成学习状态丢失且无合理迁移原因。任何一项未解决不得发布 P0。
